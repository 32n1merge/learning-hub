Lesson 8: Choosing for Your Machine

Time to make it personal. Here's the exact procedure I'd run to pick a local LLM — using Qwen3.8-27B as the running example.

Step 1 — Inventory your hardware

  • GPU VRAM (the king): 8, 12, 16, 24, 32, 48 GB…
  • System RAM: matters for CPU offload and for CPU-only inference.
  • Apple Silicon unified memory: Macs share one pool — treat it like VRAM.
  • CPU/GPU vendor: NVIDIA (everything works), AMD (ROCm — GGUF fine, some formats less), Apple (MLX/Metal), Intel (GGUF, slower).

Step 2 — Budget memory: file + context + overhead

VRAM needed ≈ model file + KV cache + ~1-2 GB overhead. Rule of thumb: multiply the file size by 1.15-1.35 for a safe context budget. Qwen3.8-27B's hybrid architecture (Gated DeltaNet linear attention) keeps its KV cache unusually small, but long contexts and thinking-mode outputs still eat memory. Bigger context = more KV, always.

Step 5 — Test before you commit

Run the same short prompt suite on the candidate: one math question, one coding task, one instruction-following task, one creative task. Watch for: gibberish or repetition (too-low quant), refusal loops (wrong fine-tune), slow token rates (too big), and context truncation (too small). Then ask: would a comfortably-fitting smaller model have felt better? — that's the question that ends most upgrade loops.

Golden rules recap: 1) biggest model that fits, 2) highest quant that fits, 3) Q4_K_M (or UD-Q4_K_M) is the default, 4) calibrated quants beat naive ones, 5) format follows software, 6) if it feels dumb, A/B the same model at Q6/Q8 before jumping models — the quant may be the culprit, 7) context and thinking mode eat your headroom before the weights do.
